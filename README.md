# 麦麦小黑盒社区适配器

接入**小黑盒社区帖子评论、@ 提及和回复**。使用 MaiBot SDK `MessageGateway`，消息进入麦麦自己的聊天、人格、记忆及回复流程。适配器不调用独立 LLM。

当前为 **0.8.1 实验版本**：已实测登录、帖子评论读取、文字评论发布及多段总结新帖发布，回读确认了新帖的账号、标题和全部段落；图床上传信息及临时凭证接口可用，带图评论尚未完成真实发布联调。写请求按网页协议构造，签名和分段表单使用模拟 HTTP 请求验证。社区接口不是官方公开稳定 API，不能保证未来兼容。黑盒语音是另一套平台，不在本插件范围内。

## 首版范围

- 侧边栏扩展页面扫码登录、自动刷新扫码状态，凭证存入宿主分配的数据目录。
- 定时读取新 @ 和评论回复，首次启动只建立历史通知基线。
- 拉取原帖及楼层文字上下文，帖子已有聊天流时持续复用，具体回复目标仍保留根楼层与评论编号。
- 发送文字、图片及表情包评论，按目标消息精确回复主帖或对应楼中楼。
- 持久化通知游标和跨通知类型去重；发送确认成功后去重，失败记录允许重试。
- 麦麦的统一适配器策略控制放行范围。消息分段仍由麦麦决定；每条出站消息对应一条评论。
- 支持按分区定时主动浏览，复用麦麦的原生主动任务、人格及上下文，自行决定是否参与评论。
- 主动浏览传入原帖作者、帖子图片和评论节选；评论分条保留发言者名字、UID、回复关系和所附图片。

普通 @ 和回复通知目前仍只接入文字上下文；暂不支持私信和点赞。纯图片通知、缺失真实 UID、回复超长、未知消息段或接口字段变化会明确报错。入站异常会停止连接并保留游标，修复后重新启用；不要通过清空数据库处理，否则会重建历史基线。

出站接受标准 `image`、`emoji` 消息段的 `binary_data_base64`，解析 PNG/JPEG/GIF/WebP 并上传至小黑盒官方图床，随后随文字一起提交评论；也允许纯图片、纯表情包评论。不把图片说明当作正文，不把本地文件路径直接发到平台。单张最多 5 MB、2000 万像素，每条最多 6 张，保留原始动画及透明度。原生 `send_emoji` 工具在小黑盒需要明确指定目标 `msg_id`；未指定或目标不存在时拒绝猜测。图片处理/上传失败会标注“未提交评论”，不发送残缺文字评论；未确认成功的记录允许重试。

## 登录及启用

1. 安装插件依赖并重载插件，在 WebUI 插件配置中启用「小黑盒社区适配器」。旧版配置若为 `enabled = false`，需手动开启一次；未登录时插件只等待扫码，不运行消息连接。
2. 打开侧边栏「插件扩展 → 小黑盒互动记录」，展开 **账号管理**，点击 **生成登录二维码**。
3. 使用小黑盒 App 扫码并在手机上确认。页面每 3 秒刷新扫码状态，成功后自动保存凭证并启动消息连接。
4. 页面显示 **已连接** 后，用另一个账号发送新的 @ 或评论回复进行验证。若收到通知但宿主拒绝接收，到适配器策略中放行需要接入的会话。

二维码过期后可重新生成；取消扫码会恢复已保存账号的连接。更换账号期间暂停旧账号连接；已有凭证时可点击 **重新连接**。本页面需要支持 WebUI 页面协议 v2 的宿主及 dashboard，无需修改或构建前端。

默认配置见 `config.example.toml`，由 SDK 生成实际配置，不要把凭证写进配置。适配器平台为 `xiaoheihe`，账号 ID 为扫码账号的真实 UID。

### 查看麦麦的互动情况

侧边栏「小黑盒互动记录」按帖子汇总浏览、收到的评论和麦麦回帖。左侧可搜索帖子标题、ID 或发言人，也可筛选已回帖或有异常记录的帖子，每页 20 篇；选中后，右侧按时间顺序展示该帖所有已保存记录，每页 30 条，默认打开最新一页，可翻看更早记录。支持单独筛选浏览、收到评论和麦麦回帖。

每条记录显示发言人、北京时间、正文、处理状态和已保存的回复目标。浏览素材、长正文及回执按需展开，失败或受限原因单独显示。原帖链接可点击「选中原帖链接」后用 Ctrl+C（macOS 为 ⌘C）复制，再在浏览器或小黑盒中打开。账号和扫码登录收在「账号管理」中。记录每 15 秒自动刷新，查询只访问本地数据库，不请求小黑盒。

“已交给麦麦”表示宿主已接收，不等于麦麦已回复；只有拿到平台明确回执才显示“已发送”。“发送中或中断待核对”和“发送结果待核对”需人工检查小黑盒实际评论，不会因刷新页面自动重发。

记录从该功能启用后开始保存，不补录升级前的内容。按登录账号隔离，保存在插件的 `community.sqlite3` 中，重启后仍可查看；评论正文会保存在本地数据库中。

### 可选终端方式

保留原有命令以供无 WebUI 环境使用。在麦麦根目录运行：

```powershell
uv pip install --python .venv/Scripts/python.exe -r plugins/xiaoheihe_adapter/requirements.txt
uv run python -m plugins.xiaoheihe_adapter.login --data-dir data/plugins/maibot-team.xiaoheihe-adapter
```

命令会输出 `login.png` 的绝对路径。在图片查看器中打开，用小黑盒 App 扫码并确认。二维码成功登录或过期后自动删除。登录命令不发送评论。

默认部署的数据目录如上；多实例部署时，`--data-dir` 应指向该实例实际分配的插件数据目录。更换账号或重新登录时先停用插件，扫码后重新启用。

等日志显示 `mention`、`reply` 历史通知基线已建立，再用另一个账号在帖子评论中 @ 当前账号，确认麦麦收到新消息并回复正确楼层。

## 浏览总结与主动发帖

在侧边栏「小黑盒主动浏览」的「浏览感想与主动发帖」中，选择触发方式、发布分区，勾选「允许麦麦自动发布总结帖」并保存。默认关闭；按数量触发默认每 10 帖一次，按时间默认每 24 小时一次，也可选择两者先达到时触发。时间周期从本批首条新素材开始，无新材料不发帖。

仅累计功能启用版本开始、已成功提交给麦麦判断的浏览帖子。同一帖子只计一次，视频、读取失败或上下文提交失败不计；是否实际评论不影响计数。已成功发送的本人评论会作为感想材料，失败评论不会冒充互动经验。生成时最多节选 100 帖；按数量触发取设定数量，其余材料留给下一批。

标题及正文由宿主真正的 Replyer 一次生成，写作目标为约 200–400 字、2–4 段，复用人格、表达选择和回复 Hook，Planner 不填写正文。使用专门的长文模板，不套用日常聊天或复古短回复模板；原帖与本人评论合计节选最多 2400 字符，为 8K 模型保留人设、格式和输出空间。各段按独立正文块提交为一篇文字帖子。需要本版主程序提供 `maisaka.reply.generate`，升级后重启主程序并重载插件以注册接口和能力权限。

页面展示待总结数量、最近一次任务的标题、正文、发布链接与错误。明确失败可以「重试本轮总结」（已有正文会复用）；发送结果不确定时须先去小黑盒核对，不会自动重复发布，可「跳过本轮总结」继续后续批次。关闭主动发帖后，正在生成但尚未发送的正文也会保留并停止发布。重置每日浏览次数不会清空总结材料或发布记录。

「长文模型」可以指定宿主已配置的模型名称，留空时沿用默认 Replyer 模型。聊天专用微调模型未必具备长文写作和结构化输出能力，建议明确选择通用模型。指定模型后仍使用 Replyer 的写作、人格、表达与 Hook 链路；模型选择失败会直接报错，不切换其他模型。

## 主动浏览与自主评论

1. 登录并连接后，打开侧边栏 **小黑盒主动浏览**。
2. 点击 **刷新小黑盒分区**，搜索名称、分组或 ID，勾选要浏览的真实分区（最多 20 个）。不使用推荐流标签模拟分区，接口失败时不替换为其他来源。
3. 设置浏览间隔和每轮判断数量。浏览与主动评论不设每日次数上限。
4. 勾选 **启用主动浏览及自主评论**，点击 **保存并应用**。配置按账号保存在插件数据库，立即生效；默认不开启主动浏览。

页面上的 **重置今日浏览次数** 仅将当前账号今天的帖子判断统计归零。重置按北京时间计算并持久化，不影响每帖评论次数、帖子去重或历史互动记录；其他账号及次日计数不受影响。

默认每 300 秒浏览一次，每轮从所选分区各读取首页最多 10 篇帖子，跨分区去重后最多提交 2 篇给麦麦判断。每日浏览与评论统计仅用于展示，不限制继续浏览或发送；每帖成功评论 3 次、后续普通回复加 3 次的规则继续生效。实际调度随通知轮询执行，可能晚于配置的浏览间隔。自己发布的帖子不参与；自动排除含视频的帖子，信息流与详情双重检查，视频不进入模型、不计入每日浏览统计。已登记的判断任务（含上下文构造失败的任务）不会重复提交；详情读取失败会记录错误，后续扫描可重试。

评论详情请求显式读取第一页（最多 20 组楼层），解析评论分组及楼中楼关系，再按上下文预算节选。平台显示有评论但返回空列表时，主动浏览会报告读取异常；只有明确返回评论数为零时才显示评论区为空。

帖子通过 SDK 图文上下文接口提供给麦麦，随后触发原生主动任务。原帖与每条评论各自作为一条可回复的 user message，保留真实作者、消息 ID 和图片归属。原帖包含标题、作者昵称/UID、原帖链接及正文；评论保留评论者昵称/UID、评论编号和楼中楼回复对象。麦麦选择原帖 target 时发送主帖评论，选择评论 target 时回复该评论，楼中楼沿用正确的根楼层。互动记录的正文同时保存这些文字材料，图片字节不写入插件数据库。需要宿主支持 `maisaka.context.append(replyable=True, user_info=...)`，旧宿主会明确报告不支持。

每篇帖子最多提供 20 条评论和 6 张图片，总文字受 `community.context_max_chars` 限制。评论按接口返回顺序节选，长正文和评论截取时明确标注，不声称读到了整个评论区。图片从小黑盒媒体域名下载，下载、解码和预览体积均有上限；大图缩到最长 1280 像素，动图取首帧。图片加载失败或超出数量限制会在对应发言下明确说明，纯图片帖若所有图片都读取失败则停止该次判断。

实际图片作为标准 `image` 段附在各自作者的消息中，需要宿主 planner/replyer 所用模型配置了视觉能力才能读取；插件不额外调用独立识图模型，纯文字模式会显示图片不可读提示。`[cube_…]` 这样的平台表情文本会保留，不会虚构它没有返回的图片地址。

麦麦可以不参与，不会为每篇帖子强制生成评论；没有拿到发送回执时，互动记录仅表示“已提交麦麦自主判断”，不会编造“已跳过”的结论。改动只影响之后新浏览的帖子，已有上下文不会自动重写，原有帖子去重记录继续保留。

主动评论默认每天最多尝试 10 篇帖子，同一帖的失败重试不额外占用篇数，按北京时间计算并持久化。每帖默认最多成功评论 3 次；麦麦参与后，每条普通回复麦麦的新评论再增加 3 次额度（3 → 6 → 9），这类回复产生的续聊也计入帖子次数。只有平台返回成功回执才消耗次数，失败或未确认时允许重试。关闭主动浏览后，尚未发送的主动任务会被拦截，正常收到的回复仍可处理。

帖子已进入聊天流时，@ 只追加为原流中的一条可回复用户消息，不开新流、不额外触发入站或主动召唤；没有现有流的帖子保留原来的 @ 入口。普通回复和后续主动浏览也复用该帖选定的真实流，不随根楼层切换；每条消息仍登记精确评论路由。@ 不增加也不消耗帖子主动次数，同一评论同时出现在 @ 和回复通知中只处理一次，无论先后顺序都按 @ 计算。

加额要求平台明确给出接收者为当前麦麦账号，且评论发生在麦麦已成功参与该帖之后；不会给旧通知、自己回复或其他接收者加额。成功次数、通知去重、加额记录和帖子流映射均按账号持久化，重启及“重置今日浏览次数”不会清除。

主动浏览首次建流时使用 `post:<帖子ID>:thread:browse`；首次通知建流使用根楼层标识。之后按账号固定复用该帖的实际聊天流，主动任务与普通续聊通过明确消息锚点关联帖子额度。真实会话 ID 从宿主查询或由 `chat.open_session` 返回，插件不自行计算。浏览和评论结果统一显示在原有互动记录中。

页面状态刷新只读本地数据；刷新分区目录只发送 GET，不调用模型、不发表评论。开启浏览后，模型判断及发表评论由后台定时执行，不依赖页面一直打开。接口遇到登录失效、限流或验证挑战时会报告错误，不绕过验证。

## 路由与发送记录

评论统一使用 `https://api.xiaoheihe.cn/bbs/app/comment/create`，携带网页版本 `3.0`、hkey 和版本 15 的 `_rnd` 签名，以 Cookie 鉴权，不携带 URL 身份 ID。协议参考：[网页请求构造](https://github.com/k1m0206/better-XiaoHeiHe/blob/main/src/content/api-signing.js)、[Python 协议实现](https://github.com/AaronZ345/xiaoheihe-cli/blob/main/xhh_operator/signing.py)。

外部群标识是 `post:<帖子ID>:thread:<根评论ID>`；帖子级 @ 使用 `thread:post`。显示名称使用帖子标题及楼层编号。宿主负责生成真实 `session_id`，插件不计算会话哈希。

出站目标必须匹配账号、楼层及明确的消息锚点，禁止按“最后一条通知”猜测目标。主动浏览为原帖和每条评论分别登记路由；目标缺失、引用冲突或跨帖子时拒绝发送。出站记录按宿主消息 ID 幂等，已成功消息返回同一回执，失败或未确认记录允许重新发送。

数据目录的 `community.sqlite3` 包含通知游标、路由及发送记录，`credentials.json` 包含登录凭证。请勿上传或分享凭证、二维码及数据库。页面二维码仅保存在内存，不落盘；刷新页面不会重新申请二维码或发表评论。新安装默认启用插件，未登录时等待扫码；创建代码和测试不会登录真实账号或发表评论。
